## 0. 写在最前面：给新手的导读

阅读这篇论文需要先弄懂几个常见但又容易混的术语。本节用最直白的中文一次性把它们都讲清楚，正文后续直接复用。

> **什么是 LLM？**
> Large Language Model，大型语言模型，例如 GPT、Qwen、Llama，本质是一个能根据上文 token 预测下一个 token 概率分布的神经网络。

> **什么是 Agent / 多轮 Agent？**
> Agent 指能与环境交互的「会自己拿主意」的程序。多轮 Agent 在每一步：观察环境 → 思考 → 输出动作 → 环境再返回新观察，反复多步直到任务结束。论文聚焦的就是**多轮 LLM Agent**。

> **什么是 RL（强化学习）？**
> 用奖励信号去优化策略。LLM 后训练里，「策略」就是模型本身，「奖励」一般来自环境（任务是否完成）或验证器（答案对不对）。

> **什么是 post-training（后训练）？**
> 预训练完成后再做的微调阶段，包括 SFT、RLHF、本文涉及的 RL 后训练等。SDAR 属于 post-training 范畴。

> **什么是 on-policy vs off-policy？**
> on-policy 指：训练时用的样本，是当前正在优化的同一个策略采样产生的；off-policy 指：可以用历史策略 / 别的策略产生的样本来训练。SDAR 强调 on-policy。

> **什么是 GRPO（Group Relative Policy Optimization）？**
> DeepSeekMath 提出的 PPO 变种。对每个 prompt 采样 G 条响应，把它们的奖励减去组内均值再除以方差作为 advantage，省掉了 critic 网络。算法流程在论文 Algorithm 2。

> **什么是 advantage（优势）？**
> 描述「这条 / 这个 token 的好坏」相对均值的偏离。GRPO 里 advantage 是序列级的（同一条响应里所有 token 共享一个数）。

> **什么是 OPSD（On-Policy Self-Distillation）？**
> 在 on-policy 采样的轨迹上，让一个「教师分支」对每个 token 给出概率分布，学生去对齐。OPSD 的特殊在于：教师不是另一个模型，而是**同一个 actor 加上一段特权上下文**（比如解题提示、标准答案）。

> **什么是特权上下文 c+？**
> 训练时教师能看到、推理时学生看不到的额外信息。SDAR 中具体指「**任务相关的 skill 文档**」（比如 ALFWorld 中按任务类别检索到的技能 markdown 文件）。

> **什么是 KL 散度？**
> 一个衡量两个概率分布差异的非对称指标 D_KL(p ‖ q) = Σ p log (p/q)。值越大代表 p 与 q 越不像。
> - **forward KL**：D_KL(教师 ‖ 学生)，mode-covering，让学生覆盖教师所有支持的 mode；
> - **reverse KL**：D_KL(学生 ‖ 教师)，mode-seeking，让学生集中在教师支持的某些 mode 上。
> SDAR 用的是 reverse KL（论文消融证明它最好）。

> **什么是 importance sampling 比 r_t？**
> r_t = π_θ(y_t | s_t) / π_θ_old(y_t | s_t)。把「旧策略采的样本」纠正��「新策略下的期望」。GRPO 的 clipped surrogate 用的就是它。

> **什么是 sigmoid 门控 g_t = σ(β·δ_t)？**
> 用 sigmoid 把任意实数 δ_t 压到 (0,1)，β 控制曲线陡峭度。SDAR 用它当置信权重：教师比学生更确定 → δ_t > 0 → g_t > 0.5 → 强蒸馏；教师没学生确定 → δ_t < 0 → g_t < 0.5 → 弱蒸馏。

> **什么是 detach / stop-gradient（sg）？**
> 把张量从计算图里摘下来，反向传播时不流经它。SDAR 把门控 g_t、教师 log_prob 都 detach，**梯度只流过学生**，从而避免「门控自我反馈」导致的不稳定。

> **什么是 ALFWorld / WebShop / Search-QA？**
> 三个常用 LLM Agent 基准：
> - **ALFWorld**：文本版的家居任务（拿苹果、放进微波炉、放回桌子等 6 类）；
> - **WebShop**：模拟在线购物，agent 在网页上搜索、过滤、下单；
> - **Search-QA**：让 agent 调用搜索引擎多步检索后回答问题。

理解了以上术语，我们正式进入论文。

## 1. 背景

### 1.1 研究领域

LLM 的训练分两步：**预训练**（在海量文本上做下一个 token 预测）和**后训练**（让模型学会「按要求做事」）。后训练里又有两个主流做法：

1. **SFT（Supervised Fine-Tuning）**：用人工写好的 (问题, 答案) 对去监督微调；
2. **RL（Reinforcement Learning）**：用奖励信号优化策略，代表方法 PPO / GRPO / DPO。

近两年大家发现：**当 LLM 不只是回答问题，而是要扮演 Agent 与环境多轮交互**（比如打开网页、调工具、玩文字游戏）时，光靠 SFT 学会的模式不够用，必须用 **RL 后训练**让模型在真实交互中学。这就是「**Agentic RL / Agentic post-training**」赛道。

### 1.2 这个赛道为什么难

多轮 Agent 与单轮 QA 的本质差别在于：

| 维度 | 单轮 QA | 多轮 Agent |
|------|---------|------------|
| 决策长度 | 一次输出 | 数十步连续输出 |
| 上文 | 固定 prompt | 自己上一步的输出会变成下一步 prompt 的一部分 |
| 反馈 | 一个标量奖励 | 只有任务结束才有奖励，中间步骤无反馈 |
| 错误传播 | 不存在 | 早期一个错的动作会污染后面所有决策 |

因此 RL 在这种场景下面临**信用分配（credit assignment）粗粒度**的根本性问题：模型只在一条几千 token 的轨迹结束时拿到一个 0/1 奖励，没法知道**哪些 token 是好的、哪些是坏的**。

> **什么是 credit assignment（信用分配）？**
> RL 里的核心问题：当一个轨迹获得了某个奖励，如何把这个奖励合理地「归功」到这条轨迹中具体的某个动作 / 某个 token 上。粒度越细，学习效率越高。

### 1.3 一种自然的补救：OPSD（On-Policy Self-Distillation）

研究者想到：能不能在 RL 之外再叠一个**逐 token 的密集监督信号**？办法是：让一个**教师分支**针对学生采到的每个 token，给出一个目标分布；学生去对齐。

OPSD 把这件事玩出了花样——**教师 = 学生本人 + 特权上下文**：

- 学生 prompt：`x`（原任务）
- 教师 prompt：`x + c+`（任务 + 一段特权信息，比如「答案提示」「skill 文档」）

由于二者参数共享，省掉了一个独立教师模型；又因为 c+ 真的能帮模型答得更好，所以教师生成出来的概率分布是一种「**作弊后的高质量答案**」，可以用来指导学生。这套思路在单轮推理场景中已经验证过有效（Self-Distilled Reasoner、TIP 等）。

**问题来了**：OPSD 是不是也能直接搬到多轮 Agent 里用？答案是「不能直接搬」。这就是 SDAR 要解决的核心问题。

## 2. 核心问题：OPSD 搬到多轮 Agent 会出什么事

论文给出两个**实证观察**作为方法动机，是全文最关键的两段。

### 2.1 观察一：Multi-turn OPSD Instability（多轮复合误差导致的崩溃）

学生 agent 一旦从教师支持的轨迹上漂移开，「曾经有用」的逐 token 监督信号就变得越来越不可靠。这种**复合误差**（compounding error）让：

- 每轮的 KL 散度急剧上升；
- 任务成功率灾难性下跌（论文 Figure 2 左：成功率从 0.3 一路掉到接近 0）。

**通俗解释**：教师在第 1 步给的「应该这样走」是基于「学生从一开始就走得对」的假设。学生哪怕第 3 步走错一点，第 5 步教师面对的状态就已经不在它擅长的分布里了，给出的「正确答案」反而把学生越带越偏。

> **什么是 compounding error / behavior cloning 的经典坑？**
> 这是 imitation learning 经典论文 DAgger（Ross et al. 2011）就指出的问题：训练时见到的状态分布与测试时见到的状态分布不匹配，误差会按 O(T²) 累积，T 是轨迹长度。

### 2.2 观察二：Asymmetric Trust in Privileged Guidance（特权指导的不对称信任）

在 OPSD 里，教师不是「真正的更强模型」，只是同一个 actor + 一段 c+。所以它的 token 级指导**本身就有不对称性**：

- 如果教师对某个学生采到的 token 给出**更高**概率（**positive gap**, ∆_t > 0）：说明这个 token 是被特权信息「背书」的，是学生已经能采到、但还没完全内化的好行为 → **应该强化蒸馏**；

- 如果教师给出**更低**概率（**negative gap**, ∆_t < 0）：信号就要谨慎对待。一个负 gap 可能意味着：
  1. **Skill 质量不够好**：检索到的 skill 文档本身不相关、不完整、冗余；
  2. **Skill 利用失败**：教师没把 skill 真正用起来；
  3. **多轮漂移**：随着 turn 推进，教师-学生差距会自然变宽（论文 Figure 3 中），早期失配会被后续放大。

**关键数字**：在 Qwen2.5-3B 上，**negative-gap 的 token 占比超过 50%**（论文 Figure 3 左）。也就是说，「教师比学生更不确定」是一种**普遍现象**，而非偶发噪声。如果不对正负 gap 区别对待，蒸馏信号会被噪声淹没。

### 2.3 现有 hybrid 方法的不足

论文还顺便分析了现有「RL + OPSD」混合方法的问题：

- **GRPO + OPSD**（直接相加）：在多轮场景里 OPSD 梯度会**爆炸**，把 RL 的奖励信号淹没（Qwen3-1.7B 上从 46.1 掉到 32.0）；
- **RLSD**：用 self-divergence 重加权 GRPO 的 token-level advantage，但**早期教师-学生差距很大时会大幅放大更新**，KL loss 飙升（Figure 2 右）；
- **Skill-SD / TCOD**：依赖**手工设计的 curriculum**（按 turn 数 / 训练步数硬切），刚性差。

由此引出 SDAR 的核心设计哲学：「**RL 当主干，OPSD 当受控的辅助；让每个 token 自己决定自己的监督强度**」。

## 3. 近年来各种方法的对比

为方便和 SDAR 对比，把相关方法按「核心动作」「需不需要 c+」「怎么处理 token 重要性」「在多轮 Agent 上的表现」分组列出。

| 类别 | 方法 | 思路简述 | 是否需要特权 c+ | Token 重要性建模 | 多轮 Agent 上的痛点 |
|------|------|----------|-----------------|------------------|----------------------|
| Training-free | **Skill-Prompt** | 推理时 prompt 里直接拼 skill 文本 | 推理也用 | 无 | 推理时依赖检索，不能内化知识 |
| Pure RL | **GRPO** | 序列级 advantage + clipped surrogate | 否 | 无（同序列共享 advantage） | 信号太稀疏，学不深 |
| Pure RL + skill prompt | **Skill-GRPO** | GRPO 训练时 prompt 里拼 skill | 训练时拼，推理可拼可不拼 | 无 | 推理时不拼会崩，分布依赖严重 |
| Pure Distill | **OPSD** | 用 ref 策略对学生采到的 token 做 KL | 否（用 frozen ref） | 无（每个 token 同权重） | 多轮复合误差，性能崩盘 |
| Hybrid 简单加和 | **GRPO + OPSD** | RL loss + α·OPSD loss | 否 | 无 | 蒸馏梯度爆炸，Qwen3-1.7B 上 -14% |
| Hybrid 重加权 advantage | **RLSD** | 用教师-学生 gap 重新加权 GRPO advantage | 是（skill） | 仅修正 advantage | 早期 gap 大时 wt 飙升导致不稳 |
| Hybrid + 课程 | **Skill-SD / TCOD** | 加 K3 散度 / 用 turn 级 curriculum | 是（skill） | 手工 schedule | 课程刚性，难调参 |
| **本文** | **SDAR** | RL 主干不变；OPSD 走 sigmoid 门控的辅助 loss；门控 detach；只有 reverse KL | 是（skill） | **token 级自适应 sigmoid 门控** | 门控自动抑制负 gap，避免梯度爆炸 |

简单说：**SDAR = "GRPO + OPSD" 的"温柔"版本**——同样把 OPSD 加进去，但每个 token 都过一道「教师可不可信」的 sigmoid 阀门，让坏信号被自动压低。

## 4. 方法详解

### 4.1 问题形式化（符号约定）

考虑一个多轮 agent 与环境交互的过程：
- 任务初始描述 `x`；
- 第 k 轮：环境给观察 `o_k`，agent 输出动作 `a_k`，环境给下一观察 `o_{k+1}`。

为了符号简单，把整条轨迹中**所有合法 response token**拉平成一个序列：

```
y = (y_1, y_2, ..., y_T)  ~  π_θ(· | x)
```

其中 π_θ 是学生策略，T 是合法 token 总数。在 token 位置 t：

- **学生上下文**：`s_t = (x, y_<t)`
- **教师上下文**：`s_t^+ = (x, c+, y_<t)`

c+ 就是特权信息（skill 文档），**只在训练时可见**。

### 4.2 Skill 的检索（论文式 1）

教师能看到的 c+ 来自 skill 库 `E = {e_1, ..., e_M}`，论文实现了 4 种检索策略：

1. **UCB Retrieval**：把 skill 选择当作多臂老虎机
   ```
   score(e) = r̄(e) + c · sqrt( ln N_ucb / n(e) )
   ```
   其中 r̄(e) 是 skill e 历史上被选时的平均奖励，N_ucb 是同任务类型下的总查询次数，n(e) 是 e 被选过的次数，c 是 exploration-exploitation 系数��
2. **Keyword Matching (KM)**：跳过 bandit，直接用任务描述里的关键词命中预定义类别。
3. **Full Retrieval**：把所有 skill 都拼到 prompt（最长但全）。
4. **Random Retrieval**：随机选一个（用作鲁棒性下界）。

> **什么是多臂老虎机（multi-armed bandit）？**
> 经典强化学习子问题：有 M 个老虎机，每次只能拉一个，每个有未知的奖励分布。要在「探索新机器」和「利用已知好机器」之间取舍。UCB 是一种经典的解法。

论文实验默认用 KM。

### 4.3 总优化目标（论文式 2 框架）

```
L(θ) = L_GRPO(θ) + λ_SDAR · L_SDAR(θ)
```

—— GRPO 是主干 RL loss，SDAR 是带门控的蒸馏辅助 loss，λ_SDAR = 0.01（论文实验最优）。

定义 mask token 平均：

```
Agg(z_{1:T}) = Σ_t m_t · z_t  /  Σ_t m_t
```

其中 m_t ∈ {0,1} 是 response mask（输入 prompt 的 token 不计入）。

### 4.4 GRPO Loss（论文式 2）

对每个 prompt x，采 G 条响应 {y^(i)}，计算序列级 advantage：

```
A^(i) = ( R(x, y^(i)) - μ_G )  /  σ_G
```

GRPO 目标（reverse-clipped surrogate + KL 罚项）：

```
L_GRPO(θ) = - (1/G) Σ_i Agg{ min[ r_t · A^(i),  clip(r_t, 1-ε, 1+ε) · A^(i) ] }
            + β · (1/G) Σ_i Agg{ D_KL( π_θ ‖ π_ref ) }
```

其中：
- `r_t = π_θ(y_t | s_t) / π_θ_old(y_t | s_t)` 是 importance sampling ratio；
- ε = 0.2 是 PPO 剪裁带宽；
- 第二项是对参考策略的 KL 罚项（防止策略漂太远）。

### 4.5 SDAR Loss：核心创新

**第一步：定义 Teacher-Student log-prob gap（论文式 3-4）**

教师对学生采到的 token 给的 log_prob 减学生自己的 log_prob：

```
δ_t = sg[ log π_θ(y_t | s_t^+) - log π_θ(y_t | s_t) ]
```

`sg` 是 stop-gradient，把这个量从计算图里摘下来。

> **为什么取 reverse KL 的 single-sample 估计？**
> 完整 reverse KL 要对全词表求和（巨贵）。论文用学生采到的 y_t 做单样本估计：
> ```
> D_RKL^(t) ≈ -[ log π_T(y_t | s_t^+) - log π_θ(y_t | s_t) ]
> ```
> 取负号就是 δ_t。它的物理含义：教师比学生确定多少 / 不确定多少。

**第二步：sigmoid 门控（论文式 5）**

```
g_t = σ( β · δ_t )
```

- **β = 5.0**：sigmoid 陡峭度。β 越大，sigmoid 越接近硬阈值；β = 0 时退化成均匀蒸馏。
- 论文给出 3 种门控变体：
  - **Entropy gating**：`g_t = σ(β · h_t)`，h_t 是学生熵���靶向「学生不确定」的 token。
  - **Gap gating**（默认）：`g_t = σ(β · δ_t)`。靶向「教师比学生确定」的 token。
  - **Soft-OR gating**：`g_t = σ(β · [1 - (1 - h_t)(1 - δ_t)])`。两者结合。

消融证明 **Gap gating 最好**（论文 Figure 6）。

**第三步：单 token loss（论文式 6）**

```
ℓ_t^SDAR = g_t · ( log π_θ(y_t | s_t^+) - log π_θ(y_t | s_t) )
```

注意：
- 教师的 `log π_θ(y_t | s_t^+)` **梯度会被 detach**（在代码 `sdar_utils.py` 里 `teacher_log_probs.detach()`），但保留在 loss 表达式里方便梯度推导；
- 学生的 `log π_θ(y_t | s_t)` **梯度保留**，反向传播会经过它。

整体 SDAR loss：

```
L_SDAR = Agg(ℓ_t^SDAR)
```

### 4.6 关键设计决策与理论支持（论文 Appendix A）

论文用 5 个 Proposition 把设计的稳健性证明出来：

1. **Proposition 1（等价的加权似然形式）**：在 g_t 和教师 log_prob 都 detach 的前提下，
   ```
   L_SDAR = C - Agg( g_t · log π_θ(y_t | s_t) )
   ```
   C 是与 θ 无关的常数。**结论**：SDAR 等价于「**带 token 权重的加权最大似然**」，每个 token 的权重就是 g_t。

2. **Proposition 2（梯度形式）**：
   ```
   ∇θ L_SDAR = - Agg( g_t · ∇θ log π_θ(y_t | s_t) )
   ```
   梯度严格被有界标量 g_t ∈ (0,1) 调制。

3. **Proposition 3（门控的单调与平滑）**：g_t 关于 δ_t 严格递增，且
   ```
   ∂g_t / ∂δ_t = β · σ(β·δ_t)·(1 - σ(β·δ_t)) ∈ (0, β/4]
   ```
   → 自然形成一个**在线 token 级 curriculum**：差距越大，权重越大，但不会爆炸。

4. **Proposition 4（梯度有界）**：若 ‖∇θ log π_θ(y_t | s_t)‖ ≤ B_t，则
   ```
   ‖∇θ L_SDAR‖ ≤ Agg(B_t)
   ```
   门控不会把辅助梯度放大到超过非加权似然梯度。

5. **Proposition 5（如果不 detach 门控会怎样）**：会出现自我引用项
   ```
   ∇θ ℓ̃_t = -[ g_t + β·δ_t·g_t·(1 - g_t) ] · ∇θ log π_θ(y_t | s_t)
   ```
   多出来的 `β·δ_t·g_t·(1-g_t)` 项会带来不稳定，所以**必须 detach 门控**。

这些理论保证了 SDAR 的训练稳定性来自**结构上的设计**而不是经验调参。

---

## 5. 为什么有效（直观解释）

回到 §2 的两个观察：

1. **多轮复合误差**：传统 OPSD 在轨迹后期被自己污染。SDAR 的 sigmoid 门控**把负 gap 的 token 软抑制**——一旦教师没把握，门控关小，蒸馏权重接近 0，这些 token 几乎不影响更新。
2. **不对称信任**：一半以上 token 是负 gap。如果对正负 gap 同等处理，等于把噪声当训练信号。SDAR 用 sigmoid 实现了**软的非对称权重**：
   - δ_t = 0 → g_t = 0.5（中性）
   - δ_t > 0 → g_t > 0.5（强蒸馏正样本）
   - δ_t < 0 → g_t < 0.5（弱蒸馏负样本）

而且 sigmoid 比硬阈值更平滑，**borderline token 也能拿到部分梯度**，避免「一刀切」漏掉有用信号。

加上：
- **不动 GRPO advantage**：保留 RL 的无偏性（RLSD 改 advantage 就破坏了无偏性）；
- **教师 = 学生 + c+，零额外参数**：省掉额外模型加载，省显存；
- **detach 全程**：门控只是权重，不参与反向传播，避免自我引用导致的不稳定。

### 7.3 训练动态（论文 §3.2，Figure 5）

- **Mean teacher-student gap ∆̄**：开局是 -0.12（教师反而比学生没把握），训练过程中逐渐爬升趋近 0。说明门控**真的找到了那部分教师能贡献价值的 token**，把它们的权重做大，于是平均 gap 改善。
- **Gate active ratio**（g_t > 0.5 的 token 占比）：早期 < 0.5（合理：那时候大多是负 gap，门控压住），训练后期上升至 ~0.55。

这两个图证明 SDAR 的门控**自适应地从「保守压制」过渡到「积极蒸馏」**，类似一个 token 级的 implicit curriculum。

## 8. 消融实验（论文 §3.4 + Figure 6/7/8/9）

### 8.1 Token-Level Gating 策略消融（Figure 6）

| 门控类型 | ALFWorld Success Rate (final) | 结论 |
|----------|--------------------------------|------|
| Entropy gating | ≈ 0.78 | 用学生熵作为代理，会错误激活到「不确定但本来就 OK」的 token |
| Soft-OR gating | ≈ 0.80 | 两个信号 OR 起来稀释了选择性 |
| **Gap gating（默认）** | **≈ 0.84** | 直接用 δ_t 最准 |

**论断**：直接用 teacher-student gap 最直接、最有效。

### 8.2 Sharpness β 消融（Figure 7）

β ∈ {0, 1, 5, 10} 上扫描：

| β | 含义 | 结果 |
|---|------|------|
| 0 | 退化成均匀蒸馏 | 继承 OPSD 的多轮不稳定，崩 |
| 1 | sigmoid 太平 | 区分度不足 |
| **5（默认）** | 最佳平衡 | 最优 |
| 10 | sigmoid 接近硬阈值 | 失去边界 token 的连续梯度 |

**论断**：β 既不能太小（区分不出来）也不能太大（变成硬阈值丢失信息）。5 是甜点。

### 8.3 Distillation Coefficient λ_SDAR 消融（Figure 8）

λ ∈ {0.001, 0.01, 0.1}：

| λ | 现象 |
|---|------|
| 0.1 | 蒸馏梯度淹没 RL，且因为平均 gap 是负的，反而让学生学坏，性能崩 |
| **0.01（默认）** | 最优 |
| 0.001 | 信号太弱，蒸馏几乎不起作用 |

**论断**：λ 必须是个「适中」的值，太大会反伤，太小没用。

### 8.4 蒸馏目标消融：Reverse KL vs Forward KL vs JSD（Figure 9）

在 Qwen2.5-7B 上比较：

| 目标 | 性能 | 论文解读 |
|------|------|----------|
| **Reverse KL（默认）** | **最好** | mode-seeking，让学生集中到教师支持的 mode；与「弱教师 + 选择性使用」哲学吻合 |
| Forward KL | 次 | mode-covering，迫使学生覆盖所有教师模式，包括不可靠的 |
| JSD | 介于两者之间 | 对称版，继承了 forward 的弊端 |

**论断**：reverse KL **天然就在做** "下采样不确定 token" 的事，与门控形成互补。

## 9. 鲁棒性 / 泛化分析（论文 §3.3）

### 9.1 Skill 检索质量鲁棒性（Table 2）

固定 λ=0.01, β=5.0，换不同检索方法：

| 检索方法 | ALFWorld | WebShop-Score | WebShop-Acc |
|----------|----------|---------------|-------------|
| UCB | 86.8 (+5.6) | 87.5 (+6.6) | 81.2 (+8.6) |
| **KM（默认）** | 85.9 (+4.7) | 89.4 (+8.5) | 82.8 (+10.2) |

### 9.2 知识内化（论文 §3.1 论断）

Skill-GRPO 推理时不带 skill 会崩（ALFWorld 80.5 → 60.2），说明它学到的是「依赖外挂」的策略；SDAR 推理时无需 skill，依然能反超 Skill-GRPO 带 skill 的版本（84.4 vs 80.5）。**这是 SDAR 的关键卖点之一**：把特权知识真的写进参数里。

## 10. 总结

### 10.1 主要贡献

1. **观察 + 命名了两个核心问题**：multi-turn OPSD instability 和 asymmetric trust in privileged guidance；
2. **方法**：把 OPSD 设计成**带 sigmoid 门控、detach、reverse-KL** 的辅助 loss，挂在 GRPO 主干上而**不动 advantage**；
3. **理论**：用 5 条 Proposition 证明门控有界、单调、非自我引用；
4. **实验**：三个模型规模、三个 benchmark 全面超越 5 个 baseline，Qwen3-1.7B 等小模型场景下提升尤其明显；
5. **鲁棒性**：对 skill 检索质量不敏感，甚至 random retrieval 也比纯 RL 强。

### 10.2 给新手的关键 takeaways

- **Hybrid RL + Distill 不能简单相加**：必须有 token 级的非对称权重，否则负样本噪声会淹没好信号；
- **Sigmoid 门控 + detach** 是把「教师相对学生的置信度」转成「token 重要性权重」的简洁优雅做法；
- **Reverse KL** 在弱教师场景下天然做了部分 token 选择，是个好默认；
- **Self-Distillation 的核心思想**：教师 = 同模型 + 特权信息，零额外参数，特别适合「skill 等可被检索的辅助知识」类场景。

### 10.3 局限 / 未来方向

- **依赖一份高质量的 skill 库**：虽然门控让随机检索都能涨点，但若 skill 库整体很糟，正 gap token 太少，效果会受限；
- **教师与学生共享参数**：如果用一个独立更强的教师可能效果更好（但失去「自蒸馏」的工程优势）；
- **β 与 λ 是手工调的**：未来可以做自适应调参；
- **当前只在三个相对结构化的 benchmark 上验证**：在更开放的 web/code 任务上需进一步验证。
